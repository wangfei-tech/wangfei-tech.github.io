# 一、进程与线程的关系

**进程（Process）是操作系统进行资源分配的基本单位，线程（Thread）是操作系统进行 CPU 调度的基本单位。**

两者最核心的关系是：

> **一个进程可以包含多个线程，进程负责提供资源，线程负责执行任务。**

例如，在你的 ROS 2 机器人导航系统中：

- 一个 ROS 2 节点可以作为独立进程运行。
- 一个进程内部可以创建多个线程。
- 多个线程可以共享进程中的内存和资源。
- CPU 实际调度执行的是线程。

## 1. 进程是什么？

进程是一个正在运行的程序实例。

例如执行：

```bash
ros2 run demo_nodes_cpp talker
```

操作系统会创建一个进程。

这个进程拥有自己的：

- 虚拟地址空间
- 堆内存
- 全局变量
- 文件描述符表
- 线程及其他运行资源

不同进程通常拥有相互隔离的虚拟地址空间。

例如：

```text
Linux 操作系统
│
├── 进程 A：slam_toolbox
│
├── 进程 B：controller_server
│
├── 进程 C：planner_server
│
└── 进程 D：rviz2
```

这些进程可以独立运行。

如果 `planner_server` 进程崩溃，通常不会直接导致 `slam_toolbox` 进程崩溃。

但如果它们作为组件运行在同一个进程中，则不能保证这种故障隔离。

---

## 2. 线程是什么？

线程是进程内部的一条执行路径。

例如：

```text
进程 A：机器人导航程序
│
├── 线程 1：接收激光雷达数据
│
├── 线程 2：执行路径规划
│
├── 线程 3：执行运动控制
│
└── 线程 4：发布机器人状态
```

四个线程属于同一个进程。

它们共享：

- 进程的虚拟地址空间
- 全局变量
- 堆内存
- 文件描述符等进程资源

但是每个线程拥有自己的：

- 栈空间
- 程序计数器（PC）
- CPU 寄存器上下文
- 线程 ID

例如：

```cpp
#include <iostream>
#include <thread>

void task1()
{
    std::cout << "Task 1" << std::endl;
}

void task2()
{
    std::cout << "Task 2" << std::endl;
}

int main()
{
    std::thread t1(task1);
    std::thread t2(task2);

    t1.join();
    t2.join();

    return 0;
}
```

这里：

- `main()` 对应主线程。
- `t1` 是新创建的线程。
- `t2` 是新创建的线程。

**整个程序通常只有一个进程，但有三个线程。**

三个线程可以并发执行，如果分配到不同的 CPU 核心，也可以并行执行。

# 二、进程与线程的主要区别

| 对比项 | 进程 | 线程 |
|---|---|---|
| 基本定义 | 程序运行的实例 | 进程中的执行单元 |
| 资源分配 | 资源分配的基本单位 | 共享所属进程的资源 |
| CPU 调度 | 进程是线程的容器 | CPU 调度的基本单位 |
| 内存空间 | 不同进程通常相互隔离 | 同一进程内线程共享地址空间 |
| 创建开销 | 通常较大 | 通常较小 |
| 切换开销 | 通常较大 | 通常较小 |
| 数据通信 | IPC、共享内存等 | 共享变量、队列等 |
| 安全性 | 隔离性较强 | 一个线程出错可能影响整个进程 |
| 崩溃影响 | 通常不直接影响其他进程 | 可能导致整个进程崩溃 |

需要注意：进程间也可以通过共享内存实现高效通信，因此不能简单认为进程之间一定不能共享数据。

# 三、进程与线程的内存关系（面试重点）

假设有两个进程：

```text
进程 A                         进程 B
┌──────────────────┐          ┌──────────────────┐
│      代码段       │          │      代码段       │
├──────────────────┤          ├──────────────────┤
│      全局变量     │          │      全局变量     │
├──────────────────┤          ├──────────────────┤
│      堆内存       │          │      堆内存       │
├──────────────────┤          ├──────────────────┤
│   线程1的栈空间   │          │   线程1的栈空间   │
├──────────────────┤          ├──────────────────┤
│   线程2的栈空间   │          │   线程2的栈空间   │
└──────────────────┘          └──────────────────┘
```

同一进程内部：

**共享的资源：**

```cpp
int global_count = 0;
```

线程 1 和线程 2 都可以访问 `global_count`。

**不共享的执行状态：**

每个线程都有自己的调用栈。

例如：

```cpp
void task()
{
    int count = 10;
}
```

如果两个线程同时执行 `task()`，它们各自拥有独立的局部变量 `count`。

但要注意：局部指针变量虽然位于各自的栈中，仍然可以指向同一块共享内存。

### 多线程为什么需要互斥锁？

例如：

```cpp
int count = 0;

void increment()
{
    for (int i = 0; i < 10000; i++)
    {
        count++;
    }
}
```

假设两个线程同时执行 `increment()`。

理论上希望：

```text
count = 20000
```

但由于 `count++` 不是原子操作，两个线程可能出现数据竞争。

解决方法：

```cpp
#include <mutex>

std::mutex mtx;
int count = 0;

void increment()
{
    for (int i = 0; i < 10000; i++)
    {
        std::lock_guard<std::mutex> lock(mtx);
        count++;
    }
}
```

通过互斥锁确保同一时刻只有一个线程修改 `count`。

# 四、结合 ROS 2 理解进程与线程

这是机器人算法工程师面试中比较容易涉及的内容。

### 1. ROS 2 节点一定是一个进程吗？

**不一定。**

ROS 2 中的 Node 是逻辑上的计算单元，不一定对应独立的操作系统进程。

例如：

```bash
ros2 run nav2_planner planner_server
```

通常会创建一个独立进程。

但是 ROS 2 支持组件化：

```text
component_container
│
├── PlannerServer
├── ControllerServer
├── BehaviorServer
└── SmootherServer
```

这些 Node 可以运行在同一个进程中。

优点：

- 减少进程数量。
- 节省部分系统资源。
- 支持进程内通信。
- 在满足条件时减少消息序列化和数据复制。

缺点：

- 节点之间的故障隔离性下降。
- 一个节点发生严重内存错误，可能导致整个容器进程崩溃。

### 2. ROS 2 Executor 与线程是什么关系？

ROS 2 中的 Executor 负责调度执行回调函数。

常见两种：

**SingleThreadedExecutor：**

```cpp
rclcpp::executors::SingleThreadedExecutor executor;
```

使用单个线程执行回调。

例如：

```text
线程1
  │
  ├── 激光订阅回调
  │
  ├── 定时器回调
  │
  └── Action相关回调
```

这些回调不会在这个 Executor 的同一执行线程上同时执行。

**MultiThreadedExecutor：**

```cpp
rclcpp::executors::MultiThreadedExecutor executor;
```

使用多个线程调度回调。

例如：

```text
进程：controller_server
│
├── Executor线程1：激光订阅回调
│
├── Executor线程2：控制定时器回调
│
└── Executor线程3：Action回调
```

但需要注意：

**使用 MultiThreadedExecutor 不代表所有回调都能够并行执行。**

回调能否并行还取决于 Callback Group。

例如，属于同一个 `MutuallyExclusive` Callback Group 的回调，即使使用多线程 Executor，也不会并行执行。

# 五、Linux 如何查看进程与线程？

你使用 Ubuntu 22.04，可以直接通过 Linux 命令观察。

### 1. 查看进程

```bash
ps -ef | grep slam_toolbox
```

### 2. 查看某个进程的线程

```bash
ps -T -p <PID>
```

例如：

```bash
ps -T -p 12345
```

输出可能为：

```text
PID    SPID   TTY    TIME     CMD
12345  12345  ?      00:00:01 slam_toolbox
12345  12346  ?      00:00:02 slam_toolbox
12345  12347  ?      00:00:03 slam_toolbox
```

其中：

- PID：进程 ID。
- SPID：线程 ID。
- 相同 PID 说明属于同一个进程。

### 3. 实时查看线程 CPU 占用

```bash
top -H -p <PID>
```

这个命令非常适合排查 ROS 2 多线程节点 CPU 占用过高的问题。

# 六、面试中如何回答？

如果面试官问：

**“进程和线程有什么区别？它们之间是什么关系？”**

可以这样回答：

> 进程是操作系统资源分配的基本单位，线程是 CPU 调度的基本单位。
>
> 一个进程至少包含一个线程，也可以包含多个线程。
>
> 同一个进程中的线程共享虚拟地址空间、堆内存和全局变量等资源，但是每个线程拥有独立的栈、寄存器上下文和程序计数器。
>
> 相比进程，线程的创建和切换开销通常更小，但多线程共享数据时可能产生竞争，需要使用互斥锁、原子变量等机制保证线程安全。
>
> 在 ROS 2 中，一个节点不一定对应一个进程。通过 Component Container，可以让多个节点运行在同一个进程中，并通过 MultiThreadedExecutor 实现回调的并发调度。

### 最后再记住三个容易考的知识点

1. **并发不等于并行**：并发强调多个任务在一段时间内交替推进，并行强调多个任务在同一时刻真正执行。
2. **多进程不一定比多线程慢**：不同进程可以分别运行在不同 CPU 核心上，进程间共享内存也可以很高效。
3. **多线程不一定提高性能**：如果任务存在大量锁竞争、线程切换或内存带宽瓶颈，增加线程反而可能降低性能。

**对于你的 ROS 2/Nav2 项目，建议重点掌握：进程与线程的区别、互斥锁、死锁、线程安全、SingleThreadedExecutor、MultiThreadedExecutor 和 Callback Group。这些知识既是 C++ 面试重点，也直接关系到机器人导航系统的实时性与稳定性。**

`---------------------------------------------------------------------------------------------------`

进程可以创建多少个，主要由 **操作系统、系统资源以及进程数量限制** 共同决定。

并不是 CPU 有多少个核心，就只能创建多少个进程。

## 一、谁决定进程可以创建多少个？

主要有四个因素：

| 决定因素 | 作用 | Linux 中的体现 |
|---|---|---|
| 操作系统内核 | 管理进程创建和系统级数量限制 | `kernel.pid_max`、`threads-max` |
| 用户资源限制 | 限制用户能够拥有的任务数量 | `ulimit -u` |
| 内存资源 | 每个进程都需要一定内存 | RAM、Swap |
| 容器或服务限制 | 限制特定服务或容器的进程数量 | cgroups、systemd、Docker |

### 1. 操作系统限制

Linux 内核负责创建和管理进程。

查看系统 PID 上限：

```bash
cat /proc/sys/kernel/pid_max
```

例如输出：

```text
4194304
```

这代表 PID 编号的上限范围，**不意味着可以同时创建 4194304 个进程**。

查看系统允许的线程总数上限：

```bash
cat /proc/sys/kernel/threads-max
```

Linux 内核内部使用 `task_struct` 描述任务，进程和线程都需要相应的内核任务结构。

因此，线程同样会消耗系统任务数量资源。

### 2. 用户资源限制

执行：

```bash
ulimit -u
```

例如：

```text
63352
```

表示当前 shell 对应的用户任务数量软限制。

注意，在 Linux 中，这项限制通常统计属于该真实用户 ID 的线程数量，而不仅仅是进程数量。

### 3. 内存限制

每创建一个进程，操作系统都需要为它分配一定的资源，例如：

- 内核任务结构
- 页表等内存管理结构
- 文件描述符相关结构
- 线程栈

假设系统内存为 8 GB，并不代表能够创建固定数量的进程。

因为不同进程的内存占用差异很大。

### 4. Docker 和 systemd 限制

对于你的 ROS 2 Docker 部署环境，还需要考虑 cgroup 的 PID 限制。

查看当前 cgroup 的进程和线程数量限制（cgroup v2）：

```bash
cat /sys/fs/cgroup/pids.max
```

查看当前数量：

```bash
cat /sys/fs/cgroup/pids.current
```

如果输出：

```text
max
```

说明当前 cgroup 没有设置明确的 PID 数量上限，但仍然受其他系统资源和限制约束。

## 二、CPU 核心数量与进程数量有什么关系？

假设你的机器人 RK3576 是 8 核 CPU。

可以创建：

```text
CPU：8 核

进程：
├── slam_toolbox
├── planner_server
├── controller_server
├── map_server
├── behavior_server
├── lifecycle_manager
├── lidar_driver
├── motor_driver
├── robot_localization
└── 其他进程……
```

即使有 100 个进程，也可以运行在 8 核 CPU 上。

原因是 Linux 使用调度器管理 CPU 执行时间。

**CPU 核心数量主要影响能够同时执行多少个线程，而不是系统能够创建多少个进程。**

对于普通单线程任务：

- 1 核 CPU：某一时刻通常只能执行 1 个线程。
- 4 核 CPU：某一时刻通常可以执行 4 个线程。
- 8 核 CPU：某一时刻通常可以执行 8 个线程。

这里假设每个核心提供一个逻辑 CPU，不考虑超线程等情况。

## 三、进程数量是由程序员决定的吗？

程序员可以决定程序尝试创建多少个进程，但最终是否创建成功，由操作系统根据资源和限制决定。

例如 Linux C++：

```cpp
#include <iostream>
#include <unistd.h>
#include <sys/wait.h>

int main()
{
    for (int i = 0; i < 5; i++)
    {
        pid_t pid = fork();

        if (pid < 0)
        {
            std::cerr << "fork failed" << std::endl;
            break;
        }
        else if (pid == 0)
        {
            std::cout << "Child PID: " << getpid() << std::endl;
            return 0;
        }
    }

    while (wait(nullptr) > 0)
    {
    }

    return 0;
}
```

这段代码尝试创建 5 个子进程。

如果系统资源充足、没有触及限制，就能创建成功。

如果资源不足或达到相关限制，`fork()` 就可能失败。

## 四、结合 ROS 2 应该怎么理解？

假设你的 Nav2 系统有：

```text
map_container
nav_container
ctrl_container
```

每个 Container 是一个独立进程。

而每个 Container 内部可以加载多个 ROS 2 Node。

例如：

```text
进程 1：map_container
    ├── MapServer
    └── MapSaver

进程 2：nav_container
    ├── PlannerServer
    ├── BehaviorServer
    ├── BtNavigator
    └── SmootherServer

进程 3：ctrl_container
    ├── ControllerServer
    ├── MotorServer
    └── VelocitySmoother
```

这里一共是 **3 个进程，但有 9 个 ROS 2 节点**。

这些进程内部还可以创建多个线程。

实际工程中，需要根据 CPU 负载、内存、实时性和故障隔离需求，决定如何划分进程。

例如，将高频控制模块与计算量大的 SLAM 模块放在不同进程中，可以增强故障隔离，也便于分别监控资源使用情况。

## 五、面试如何回答？

面试官问：

**“一个系统最多能创建多少个进程？由什么决定？”**

你可以回答：

> Linux 系统能够创建的进程数量不是固定的，也不由 CPU 核心数量直接决定。
>
> 它主要受到内核配置、用户资源限制、cgroup 限制以及系统可用内存等因素影响。
>
> 例如，Linux 可以通过 `pid_max` 限制 PID 编号范围，通过 `threads-max` 限制系统线程数量，还可以通过 `ulimit -u` 限制用户任务数量。
>
> CPU 核心数量主要影响进程和线程的并行执行能力，而不是能够创建的总数量。

**另外，还有一个很重要的延伸面试题：**

如果一台 Linux 服务器只有 8 个 CPU 核心，程序创建了 100 个线程，这 100 个线程能不能同时运行？

答案是：**100 个线程可以同时处于可运行状态，但如果只有 8 个逻辑 CPU，某个瞬间最多通常只有 8 个线程真正占用 CPU 执行。** 其余可运行线程需要等待操作系统调度。
